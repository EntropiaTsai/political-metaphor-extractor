# Prompt 架構與改寫指南

說明兩份 system prompt 每個段落在做什麼、哪些能改、哪些不要動。

## 為什麼要拆成兩階段

最直覺的做法是一次問完：「找出隱喻，並標上 source domain 與 target domain」。實務上這樣做會壞掉，原因有三個。

**清單會變成觸發器。** 只要 prompt 裡出現「戰爭、動物、戲劇」這種來源域清單，模型就會開始在文本裡搜尋對應詞彙，看到「攻擊」就標戰爭，不管那句話是不是真的有跨域映射。分類任務的存在本身就污染了抽取任務。

**錯誤無法歸因。** 一筆結果錯了，你分不出是「根本不該抽出來」還是「抽得對但分類錯」。這兩種錯誤的修法完全不同：前者要改抽取規則，後者要改 taxonomy 或映射規則。

**無法獨立稽核。** 第二階段刻意看不到原文，只能根據 Tenor / Vehicle / Ground 判斷。這是個特性不是限制——如果光看這三個欄位無法判定 domain，那多半代表第一階段抽出來的三元組本身就不夠清楚，這個訊號很有價值。

代價是成本翻倍與多一層資料流。值得。

## extract_system.md

### 語料脈絡區塊（必改）

用 HTML 註解標出來的那段。要寫的是模型不可能自己知道的東西：

- 來源與文體（論壇貼文？新聞？逐字稿？）
- 語言與語域（正式書面？口語？大量縮寫黑話？）
- 該場域的政治結構（有哪些陣營、如何互稱）
- 常見的在地隱喻詞

最後一項最容易寫錯。列詞是為了讓模型看懂語境——不知道「青鳥」在台灣政治指涉什麼，就無法判斷它是隱喻還是單純的鳥。但列了詞就有被當成必抓清單的風險，所以 prompt 裡緊接著寫了「這些詞是理解語境用的背景知識，不是必抓清單」，而且驗證步驟又重申一次。**改寫時保留這兩道防線。**

寧可少列幾個詞。列得越多，模型越傾向去語料裡搜尋它們。

### 五步驟推理（不要動）

順序本身就是設計：

1. **語意焦點** 放在最前面，因為它會決定後面 Tenor 的抽法。「這個部長講的話根本是放屁」批評的是言論不是人，Tenor 應該是言論。先做這步才不會機械地把字面主詞當 Tenor。
2. **先找 Vehicle 再找 Tenor**。喻體在表層文字裡通常看得見，本體常常要推論。從看得見的往看不見的找比較穩。
3. **Ground 要求「形容詞＋名詞」短語**。不限制格式的話會得到一整句解釋，沒辦法用來做後續的中層規則比對。
4. **驗證步驟做的是排除**。這是抑制假陽性的主要機制，佔了整個 prompt 最大篇幅是刻意的。

### 排除規則（跨語料通用，不要刪）

四條，每一條都對應一類實際踩過的坑：

- **代稱不是隱喻**——沒有新的跨域屬性映射、只有指稱功能的綽號要排除。最大宗的假陽性來源。
- **空泛評價不是來源域**——單純的罵人詞、情緒詞無法穩定映射到可感知來源域。
- **字面解釋優先**——能完全用字面讀通且與政治語境無關的（在講天氣、食物），排除。
- **證據句必須切題**——離題插話不算。

### Vehicle 正規化規則

這條很細但很重要：`走狗` 不能簡化成 `狗`。判準是「移除修飾語會不會改變來源概念或政治指涉」。`那隻狗` → `狗` 可以，`走狗` → `狗` 不行，因為前者的修飾語只是指示詞，後者的「走」把「狗」變成了一個詞彙化的政治貶稱。

換語料時把例子換成該語言的對應現象，規則本身照抄。

### 輸出格式

強制 `results` 涵蓋每一個輸入 `text_id`，沒有隱喻也要給空陣列。少一筆，比例統計的分母就錯了。腳本模式會回報缺漏，agent 模式由 `ingest_annotations.py` 回報。

## map_system.md

### 白名單注入

`{{allowed_target_domains}}`、`{{allowed_source_domains}}`、`{{invalid_source_terms}}` 三個佔位符會在執行時被 `taxonomy.yaml` 的內容替換。

這樣設計是為了讓 prompt 看到的標籤空間和事後驗證用的白名單**永遠是同一份**。原始專案曾經把兩者分開寫，結果 prompt 裡有的標籤白名單裡沒有，模型照 prompt 給出合法答案卻被驗證階段丟掉，靜默損失了資料。

所以：**要增減標籤，只改 `taxonomy.yaml`，不要改 prompt。**

### 留空優於硬猜

prompt 明確允許輸出空字串，但也明確說「不要因為粒度不確定就留空」。這兩句不衝突：粒度不確定時選最接近的上位概念，但關係根本不成立時就留空。

同時禁止輸出 `OTHER`。有 `OTHER` 這個選項，它就會變成垃圾桶，而且是個看起來合法、會混進統計的垃圾桶。留空至少會被 `mapping_valid=0` 誠實標記。

### 層級校正的 few-shot

四個範例裡有兩個專門處理層級混淆，因為這是實際跑起來最常錯的地方：

- **角色 vs 場域**：Vehicle 被當作角色主體時取 `表演者`，而不是場域層級的 `戲劇/娛樂`。
- **人 vs 行為**：Vehicle 是人（黑道、流氓）取 `犯罪者`；是行為（作案）取 `犯罪`。

換語料時保留這兩個範例的**結構**，把例子換成你領域的對應狀況。範例的作用是示範推理路徑，不是提供詞彙對照。

## 換領域（不只是改語料脈絡區塊）

語料脈絡區塊是為了「換一批**政治**語料」設計的：換國家、換平台、換語言都靠它。換**領域**是另一回事，改那個區塊不夠。

兩份 prompt 把政治假設寫進了推理步驟本身。抽取階段：persona 自稱研究政治隱喻、步驟 1 要求語意焦點落在政治層面、步驟 3 要求 Tenor 是真實政治對象、步驟 5 驗證時要求能與政治語境建立映射、輸出規則說「無明確政治隱喻就給空陣列」。映射階段更直接，核心原則第一條禁止把非政治對象標成 target。

這些條款會**主動排除**其他領域的合法隱喻，不是只讓品質下降。醫療語料的「癌細胞入侵器官」是教科書等級的 ILLNESS IS WAR，但 Tenor 是疾病不是政治對象，會被步驟 3 與步驟 5 擋掉。

真的要換領域，要動的是：

- 兩份 prompt 裡所有把 target 限定為政治的措辭（上面列的那些）
- `參考概念` 與全部 few-shot，換成該領域的真實隱喻
- `allowed_target_domains` 整份重寫
- `hierarchy_rules.yaml` 的 `macro_target` 與 `target_merge`

`allowed_source_domains` 大半可以留著。戰爭、動物、商業、宗教、戲劇、家庭、階層、自然物是通用的 CMT 來源域，我們本來就是用同一小組具體概念去理解各種抽象事物。腳本則完全不含領域知識，照用即可。

## 換語言

不要用中文 prompt 去分析英文語料。整份翻成語料的語言，包含：

- 五步驟的措辭
- 排除規則
- few-shot 範例（要換成該語言真實的隱喻，不是翻譯過來的中文例子）
- taxonomy 的標籤（連帶 `hierarchy_rules.yaml` 的中層規則也要重寫）

輸出的 JSON 欄位名（`vehicle`、`tenor`、`ground`……）保持英文不變，腳本靠它們解析。

## 調整流程

改 prompt 之後，用同一小批語料（20–30 則）重跑，把新舊結果並排比較。重點看假陽性有沒有變多，而不只是看抽出來的數量。

**數量變多通常不是好事**——多半代表排除規則被削弱了。
