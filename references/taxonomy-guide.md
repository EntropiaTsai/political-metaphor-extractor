# Taxonomy 與三層本體設計

如何決定標籤空間與各層粒度。這是整套流程裡最需要領域判斷、也最影響結論的部分。

## 三層各自從哪來

| 層級 | 來源 | 可靠度 |
|---|---|---|
| macro source | LLM 從白名單中選 | 中，需抽查 |
| mid source | 你寫的關鍵詞規則 | 高，規則是確定性的 |
| sub source | 原始 vehicle，原樣保留 | 高，未經處理 |

刻意這樣切分：把需要語意判斷的部分交給模型但用白名單約束，把需要領域知識的部分留給人，把原始證據完整保留下來以供稽核。

**sub 層永遠是未經正規化的 vehicle。** 不要在這層做合併，它的用途是讓你隨時能追回原文，以及在中層規則寫錯時重新分類。

## 設計 allowed_source_domains

### 從資料裡長出來，不要從理論抄下來

正確做法是先跑一小批（50–100 則），讓第一階段自由抽 vehicle，把結果拉出來看有哪些來源概念真的出現，再據此決定標籤。

從 Lakoff & Johnson 的清單直接抄一份下來會有兩個問題：你的語料裡大半標籤是空的，而語料裡真正高頻的東西沒有標籤可放。

### 粒度判準

一個標籤要能同時滿足：

- **夠大**：在你的語料裡至少出現 5–10 次，否則統計上說不出話。
- **夠窄**：如果一個標籤佔了總量的 40% 以上，它太粗了，該考慮拆開或往中層下推。
- **可辯護**：你要能對審查人解釋為什麼這筆屬於這個標籤。

實務上 15–20 個 macro source 是合理範圍。超過 30 個通常代表你把中層的東西放到 macro 了。

### 純評價詞不是來源域

`道德`、`正義`、`錯誤` 這類詞不具備可感知的具象結構，不能當來源域。它們是評價的結果，不是用來理解政治的概念來源。

這類詞放進 `invalid_source_terms`，就算模型硬要給也會被清掉。

### 角色類與場域類要並存但分清楚

`犯罪` 與 `犯罪者`、`戲劇/娛樂` 與 `表演者` 都同時在 source 白名單裡。這不是重複，是兩種不同的映射：把政治**活動**理解為犯罪，跟把政治**人物**理解為犯罪者，是不同的隱喻。

判準寫在 map prompt 的 few-shot 裡：Vehicle 是人就取角色類，是行為或事件就取活動類。

## allowed_target_domains 的常見錯誤

**不要把 source 側的角色類標籤放進 target 白名單。** 原始專案的 taxonomy 曾經把 `犯罪者` 同時列在兩邊，結果產生了 `犯罪者 → 犯罪者` 這種無意義的映射，而且在 macro 統計裡 `犯罪者` 錯誤地跟 `犯罪` 平起平坐，變成一個假的 macro 來源域。

target 白名單裡應該只有**政治領域內**的概念：人物、政黨、政策、制度、事件、群眾、國家。

**target 側通常需要合併。** `支持者群體`、`選民`、`群眾` 在多數分析裡是同一件事，硬分開會把樣本切碎到無法比較。用 `hierarchy_rules.yaml` 的 `target_merge` 收攏：

```yaml
target_merge:
  支持者群體: "政治群眾"
  選民: "政治群眾"
  群眾: "政治群眾"
```

分開抽、事後合併，比一開始就只給粗標籤好——你隨時能改變合併方式重跑，但抽不回已經丟掉的區分。

## 寫中層規則

### 只為夠大的 macro domain 寫

沒寫規則的 macro domain 會直接用自己當中層標籤，這是合理的預設。一個只有 6 筆的來源域拆成中層沒有意義。

先跑一次 `build_hierarchy.py` 看 `stats_macro.csv`，挑前幾大的來寫。

### 比對機制

關鍵詞拿去跟 `vehicle + ground` 串起來的字串做子字串比對，**長詞優先**。

長詞優先是必要的。如果「狗」和「走狗」都是關鍵詞，按長度排序才能保證 `走狗` 落在專屬的中層，不會被通用的「狗」搶走。寫規則時不必擔心順序，腳本會處理。

因為是子字串比對，短關鍵詞要小心誤命中。`鳥` 會命中 `青鳥` 也會命中 `鳥籠`，如果這兩者該分開，就要為 `鳥籠` 寫更長的規則讓它優先。

### 殘差桶就是待辦清單

沒被任何規則命中的落進 `其他<macro>`，`is_residual_mid` 標成 1，而且**被排除在統計表之外**。

`build_hierarchy.py` 每次都會印出殘差桶大小。流程是：跑 → 看殘差 → 補規則 → 再跑。反覆幾輪直到殘差比例可接受。

殘差要壓到多低沒有硬標準，但要在論文裡誠實報告。原始專案的口徑是 591 筆有效映射中 454 筆進入乾淨中層，76.8%，其餘落在殘差桶或未通過人工複審。

**不要為了把殘差清零而寫過度寬鬆的規則。** 留一個誠實的殘差桶，比塞進勉強的分類好。

## 迭代節奏

taxonomy 不會一次到位。合理的節奏是：

1. 小批試跑（50 則），看 vehicle 分布，草擬 macro 標籤
2. 跑完整語料的第一階段，看被拒絕的標籤，補齊白名單
3. 寫中層規則，看殘差，補規則
4. 人工抽查，發現層級混淆，修正 prompt few-shot 或標籤定義
5. 重跑受影響的階段

**每次改動 taxonomy 都要記錄下來。** 論文的方法章節需要交代標籤是怎麼決定的，事後回想不可能想得起來。改動理由比改動本身更難重建。
